# ESP32-S3 N16R8 固件（MVP bring-up）

## 环境

- Arduino IDE 2.x
- Espressif **Arduino-ESP32** platform（建议使用当前稳定版 3.x）
- Board 可先选 `ESP32S3 Dev Module`；Flash/PSRAM/USB 上传选项必须按购买的具体 N16R8 开发板资料设置。

官方 Arduino-ESP32 支持 ESP32-S3，参见 <https://docs.espressif.com/projects/arduino-esp32/en/latest/getting_started.html>。

## 当前实现边界与已知限制

这是人工串口 bring-up 草案，不是自动任务控制器。编码器目前仅统计 A 相上升沿，没有方向判定、速度闭环或基于里程的返航。**按官方题面要求，本车载固件不包含卸载执行器**：题目规定的卸载装置必须与车辆分离、原创自制，且允许队员直接人力操作。超声波无回波会阻止/停止运动，属于保守策略，但不能代替硬件急停。代码尚未在 Arduino-ESP32 实际工具链中编译，因此 API/版本兼容性仍需构建验证。

## 本固件当前做什么

- 上电默认电机 disarmed，四路 PWM 和 GPIO21 共享驱动使能初始化为关闭状态；每次运动脉冲结束后先关 PWM 再拉低使能。
- 串口命令：`help`、`status`、`arm`、`disarm`、`fwd`、`rev`、`left`、`right`、`stop`、`unload`。
- 低占空比、短时电机测试脉冲；脉冲超时自动停机。
- 读取两个编码器 A 相、两个超声波近距离读数和两个限位开关。
- 不提供 `unload` 命令；题目要求的卸载装置是独立的人力操作机构，不由车辆固件驱动。

**这不是完成版自动驾驶/返航程序。** 当前没有实现可靠的路线定位、任务状态机闭环、自动缺货感知、购物车释放规则或真实机械卸货验证。Python 替代品模块目前独立运行。

## 接线表

| 功能 | GPIO |
|---|---:|
| 左驱动 RPWM / LPWM | 4 / 5 |
| 右驱动 RPWM / LPWM | 6 / 7 |
| 两块驱动器共享 R_EN/L_EN 使能 | 21 |
| 左 / 右编码器 A 相 | 15 / 16 |
| 左 HC-SR04 TRIG / ECHO | 10 / 11 |
| 右 HC-SR04 TRIG / ECHO | 12 / 13 |

本表是候选映射。购买前后都必须对照实际开发板丝印/原理图；不同第三方板子的板载 LED、USB、模组引脚引出可能不同。

## 上电前必须做

1. **HC-SR04 ECHO 不可直连 ESP32-S3。** 常见模块输出 5V，必须分压或电平转换，进入 GPIO 的电压不得超过 3.3V。
2. 核对编码器输出电平；若高于 3.3V，先做电平适配。
3. BTS7960/IBT-2 的 R_EN/L_EN 不得悬空；先确认具体模块的逻辑输入阈值、使能接法和电机堵转电流。若 3.3V 控制不可靠，使用合适的逻辑电平转换或改用确认兼容的驱动器。
4. 两块驱动器的 R_EN/L_EN 按具体模块接到 GPIO21 共享使能（仅当 3.3V 逻辑兼容；否则加电平转换），并加外部下拉，确保复位时禁用。急停必须用硬件切断电机驱动电源，不能仅靠 ESP32 程序。首次上电时抬起车轮，电机电源与 USB 供电分开检查。
5. 先测试 USB 下载与串口，再单侧电机，再传感器，最后低速整车。

## 串口操作

连接串口，波特率 115200，发送命令并以换行结尾。车轮离地时先执行 `status`，确认输出安全；只有完成接线审查并确认硬件急停有效后才可执行 `arm`。运动命令为有限时长脉冲，不要将其当作自动导航。

硬件/固件编译和实机测试尚未在本仓库操作环境中验证；每次实测都应记录固件 commit、板型、库版本、电源和结果。
