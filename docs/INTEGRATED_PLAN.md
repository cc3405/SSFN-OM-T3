# 整合方案与冲突裁决

## 1. 目标与边界

在北京市海淀区、14 天内制作一个能真实演示并按清单验收的 OMER 购物服务原型。验收目标是任务链完整、行为可解释、成本可追溯和失败可恢复；不是承诺满分或声称未经实测的性能。

约束来源：
- D5：`D5/1111111-main/要求.txt`、赛题 PDF、技术方案和 Arduino 草稿。
- 三组：`3组/OM计划.txt`、剧本、预算表与小车设计图。
- 规则冲突最终以赛题原文与官方书面澄清为准；此后优先三组材料。

## 2. 冲突裁决表

| 议题 | D5 倾向 | 三组倾向 | 最终决定 |
|---|---|---|---|
| 实施节奏 | 多模块自动化，设计文档覆盖较广 | 30 天计划强调先跑通任务链 | 压缩为 14 天分阶段 MVP；按门槛逐项启用 |
| 缺货替代 | 牛奶缺货后由购物助理批准豆奶替代 | 替代品必须由程序内置规则自主选出，不靠人遥控 | 程序按固定规则选出唯一候选；助理只作舞台确认，不改变算法结果 |
| 导航 | 编码器 + MPU6050 + 航点状态机 + 无线接管 | 先保证基本移动和任务链，避免只依赖黑线 | 第一阶段低速遥控/人工标记定位；自动航点为可选升级，未实测不作为关键路径 |
| 卸货 | 独立电动回转臂，含多个限位开关 | 优先简单、可靠的卸料翻斗/夹爪，先测卸货成功 | 先做最少执行器、重力辅助的独立卸货模块；仅在单次 10/10 稳定后评估回转臂 |
| 购物车回位 | 电机、离合器、霍尔测距、定距驱动 | 强调整体流程完成及失败预案 | 先验证规则对“自行行进”的解释及官方澄清；硬件方案未获确认前不把主动驱动回位视为合规已定 |
| 文档与工具 | 包含依赖特定工作台的 `doc_driver.py` | 关注比赛实物交付 | 该脚本不是核心运行依赖；因使用固定绝对路径和外部专有 SDK，14 天 MVP 不依赖它 |
| 预算 | D5 草案估算总额约 160 美元、余量约 5 美元 | 三组预算表为材料准备参考 | 以实际购买凭证重算；预算余量不足或单项价格未知时，先做低成本替代，不把估价当报价 |

## 3. 最小可交付架构

### A. 任务控制

采用清晰、可复位的有限状态机，最少包含：

`IDLE → ORDER_RECEIVED → SELECT_SUBSTITUTE → PICK_ITEMS → UNLOAD → CART_RELEASE_CHECK → RETURN/STOP → DONE`

每个状态必须有：进入条件、执行动作、成功条件、超时/失败处理和人工恢复方式。任何无线失联、异常重启或急停触发都必须进入停止状态，不能继续自动动作。

### B. 缺货替代规则

1. 订单清单在起始线前交给操作员（依赛题及官方澄清核对）。
2. 货架缺货由预先配置的测试输入/开关明确表示；14 天 MVP 不宣称已实现计算机视觉识别。
3. 规则引擎按确定性规则选出替代品：同类优先、预算不超限、候选排序固定；没有合法候选则安全停机并给出“需人工处理”状态。
4. 系统显示/记录原商品、缺货状态、替代候选和规则原因。
5. 购物助理公开批准舞台中的替代结果，但不允许通过遥控临时改选算法结果。比赛规则如要求其他批准方式，以官方文字为准。

### C. 车辆与机械

- 先做低速直行、转向、停车、急停与失联停车。
- 取货、装载、卸货分别作为独立机构测试，不在机构不稳定时串联全流程。
- 购物车主动回位涉及“自行行进”的规则解释，需先取得官方澄清；未经确认不得把它当作已合规方案。
- 乘员脚踏、重心、夹点、电池固定和运动范围必须由成人/教练现场检查；测试时先使用假负载，不载人。

### D. 舞台呈现

沿用三组太空补给站世界观与角色关系。剧情必须围绕真实动作展开，不能用台词或道具掩盖技术任务失败。先用计时器把技术任务控制在 6 分钟内，预留约 2 分钟给开场、过场与谢幕；具体分配经实测后冻结。

## 4. 依赖与工程门槛

- Arduino 草稿引用 `RF24`、`Servo`、`Wire`、`SPI`、`Adafruit_GFX`、`Adafruit_SSD1306` 等库。编译前必须记录板卡型号、库版本、引脚映射和供电。
- D5 的文档生成脚本依赖特定绝对路径下的 EDSDK，且使用共享临时 JSON 文件；不属于可移植依赖，默认从比赛交付链路剔除。
- 车辆与购物车固件可能部署在不同控制板上；需分别编译，不能将多个含 `setup()/loop()` 的 `.ino` 文件当成同一个 Arduino sketch 一起编译。
- 在硬件未到位时，先进行静态检查和模拟/桌面逻辑测试，报告必须明确区分静态检查、编译测试和实机测试。

## 5. 版本门槛

- **MVP-1**：底盘安全移动与停止可重复。
- **MVP-2**：替代规则能用固定测试输入确定性选品；助理展示流程完整。
- **MVP-3**：单件取放/卸货成功率达到团队预设门槛并有记录。
- **MVP-4**：购物车释放/回位通过规则审查与重复实测。
- **演示候选**：连续 5 次完整流程无关键安全/规则失败；若未达成，演示降级为分段展示并如实标注。
