# 验收与测试清单

状态约定：`未测`、`通过`、`失败`、`阻塞`。没有测试记录的项目一律为“未测”，不能写“通过”。

| ID | 验收项 | 方法 | 通过条件 | 当前状态 |
|---|---|---|---|---|
| R-01 | 订单在起始线前交付 | 录像并逐帧核对 | 清单交接发生在车辆越线前 | 未测 |
| R-02 | 缺货替代选择可解释 | 覆盖所有预设输入 | 同输入同结果，记录原因；无候选则安全停止 | 未测 |
| R-03 | 助理批准/展示替代品 | 全流程彩排 | 口头/道具展示明确，且不临时改变算法输出 | 未测 |
| R-04 | 购买/装载三件物品 | 逐件计数与录像 | 三件均能辨认并正确记录 | 未测 |
| R-05 | 卸货装置独立于车辆 | 现场检查 | 机械/电气连接关系符合赛题要求 | 未测 |
| R-06 | 购物车释放和终点 | 尺寸测量 + 录像 | 按赛题原文及正式澄清判定 | 阻塞：需确认主动回位解释 |

## C. 证据记录模板

每一轮测试至少记录：

- 日期与地点（海淀区具体场地由团队自行填写）
- 操作员、观察员、硬件版本、固件 commit、配置
- 场地尺寸、负载、电池状态、环境条件
- 测试步骤、预期结果、实际结果、通过/失败
- 失败描述、复现步骤、修复 commit、回归结果
- 视频/照片/预算凭证链接

## D. 静态检查的限制

源码浏览只能帮助发现风险，不能证明 Arduino 编译通过、传感器读数正确、无线稳定、机械结构安全或比赛规则合规。硬件验收必须在实际设备上完成，并保留原始证据。
