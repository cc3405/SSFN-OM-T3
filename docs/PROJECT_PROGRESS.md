## 3. 当前阻塞项与完成定义

### P0 — 规则与安全阻塞项

- [ ] **确认队伍组别。** 负责人：队伍；证据：报名/组别确认。
- [ ] **核对当季活动手册与最新官方澄清。** 逐条记录可能影响车辆、卸货装置、成本、外部援助、提交材料和计分的条款；证据：补充规则追踪表及来源/版本日期。
- [ ] **制作独立卸载装置。** 必须与车辆完全分离、原创且由队伍制作（可使用商业零件），可由队员直接人力操作；证据：结构照片/尺寸、与车辆分离检查、三件物品从购物车进入结账区的连续视频。
- [ ] **完成电气安全审查。** 对照具体开发板、驱动器和电机数据手册，核验电压、逻辑电平、堵转电流、导线、保险丝和供电；证据：实物接线图、型号/数据表、测量记录。
- [ ] **验证硬件急停。** 急停必须能物理切断电机驱动能量，不能只依赖软件命令；证据：电机运转与控制器异常情形下的测试记录。

### P1 — 集成与性能

- [ ] 在明确的 Arduino-ESP32 版本下完成固件编译、上传和启动检查；归档完整构建日志。
- [ ] 对每个 GPIO 实测输入电压，确认 ESP32-S3 输入不超过其允许范围；特别检查超声波 Echo 等信号。
- [ ] 验证低速直行、转向、停止、失联停止和编码器计数；记录每项重复次数和失败原因。
- [ ] 在真实尺寸场地验证购物车挂接、推进、越起始线、停车、释放及最终停区；录像需能清楚看到车辆和购物车相对起始线的位置。
- [ ] 演练缺货替代流程，区分“程序提出替代品”与“购物助理按题面确认”的动作。
- [ ] 完成完整 8 分钟任务/表演计时排练，并检查规定的提交材料。
- [ ] 完整流程连续 5 次通过；保留视频、日志、固件 commit 和硬件配置。未达到之前不得标记为通过。

### P2 — 采购与交付整理

- [ ] 评估并制作商品抓取机械臂样机；核算道具质量、臂长、舵机力矩、峰值电流和车体稳定性。机械臂不得替代独立人力卸载装置。\n- [ ] 获取准确开发板、驱动器、电池和机械件的实时报价及采购凭证。
- [ ] 按赛事成本规则核算 US$165 上限；记录汇率/日期及任何适用例外的官方依据。
- [ ] 检查仓库文档中的型号、引脚、状态和测试命令是否相互一致。
- [ ] 清理旧分支前先比较各分支独有提交，确认有用改动已合并且无未保存工作；不因分支名称看起来旧就直接删除。

## 5. 每次工作更新的记录格式

每次完成一项工作，追加一行记录：

| 日期 | 任务/PR/提交 | 改动或实验 | 结果 | 证据链接 | 后续问题 |
|---|---|---|---|---|---|
| YYYY-MM-DD | 例如 PR #N / commit SHA | 简述 | 通过 / 失败 / 阻塞 / 未测 | 视频、日志、照片、来源 | 未关闭事项 |

**状态规则：**
- “已合并”只代表 GitHub 仓库变更已进入 `main`。
- “通过”必须有可复核证据；没有证据时标记“未测”。
- 失败必须保留复现步骤和修复后的回归结果。
- 官方题面、活动手册或澄清发生变化时，应记录来源、发布日期/版本并重新检查受影响的设计。
- `3组/` 是严格保护目录；所有工作记录、代码和新文档放在该目录之外。
